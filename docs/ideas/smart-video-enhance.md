# 智能画质增强（SkyPlayer 画质主线演进）

> 由 idea-refine 会话产出（2026-06-11）。
> 背景：LUT 画质滤镜已落地（78eb439），本文回答"画质能力在产品形态上如何构成 C 端竞争力"。

## Problem Statement

HMW 让低码率/暗场景片源在 SkyPlayer 上"开播即变好看"，且让用户感知到这份提升，构成 C 端选择这个播放器的理由？

## Recommended Direction

从"滤镜面板"升级为"智能画质增强"。判断依据：调色滤镜（5 个预设 + 强度滑杆）是 C 端播放器的标配维生素，不构成选择理由；被市场验证的付费点是"把烂片源变好看"（夸克/百度网盘的 AI 增强会员、B 站动漫超分）。用户的真实 job 不是"给视频调色"，而是"这片源太糊/太暗，想看得舒服"。

三件事构成主线：

1. **增强能力**：CAS 锐化 + 暗场提亮 + deband，单 pass 内联进现有 5 格式 fragment shader（GLES + Vulkan 双后端，复用 `gen_spirv.sh`），与 LUT 串联；`setLut` 链路扩展为增强参数组。
2. **智能模式**：码率/分辨率（ffplay 元数据）+ 暗场（解码帧 CPU 亮度抽样）检测，自动开启并 toast 告知；可关、记忆用户选择。
3. **可感知性**：长按看原片（按下显示原始帧，松开恢复增强）——不可感知 = 没做，这是 C 端竞争力的兜底组件。

**架构结论**：不建 filter chain 大架构。压力测试发现 CAS/提亮/deband 均可在现有单 pass 架构内通过邻域采样完成，不需要离屏 FBO 多 pass 链；filter chain 推迟到真正需要第二个 pass 的效果（降采样降噪、NN 超分）出现时再建。

**差异化**：vs MX Player/VLC——它们只有手动亮度/对比度，没有场景检测与自动增强；vs 夸克 AI 增强——云端模型 + 会员墙，我们是端侧实时、免费、离线。

## Key Assumptions to Validate

- [x] **增强效果肉眼可见**——✅ 已验证（2026-06-12，Pixel 10 真机，三种 ffmpeg 劣化片源 × 4 组合共 12 组暂停帧 A/B 截图）：
  - CAS 锐化：480p/250kbps 糊源纹理肉眼可见变清晰，Laplacian 锐度 3.9x，无光晕；对平滑渐变零改动（自适应性成立）
  - 暗场提亮：效果最显著，黑死细节全部可见，高光不过曝，暗区均值 2-3x
  - deband：色带/块状感肉眼可辨变平滑，且改动全部在 ±4 灰阶内（阈值设计"只动色带不动纹理"成立）
  - 管线顺序验证：lift 单开会放大色带，deband 前置后全开组合明显压住——deband→CAS→lift 顺序正确
  - 复跑方式：`adb push` 劣化 mp4 到 `files/spike/` 后启动 AutoTest，宿主监听 `ABTEST_MARKER` 截图
- [ ] **自动检测不误伤**（暗黑系电影被错误提亮会激怒用户）——保守阈值 + 默认"智能"档可关 + 记忆选择；不行则降级为"推荐开启"提示。
- [ ] **中端机性能可接受**（1080p 增加邻域采样后的帧时间/发热）——用现有 AutoTest 基建做帧时间打点对比；不行则增强仅对 ≤720p 源开启（反而自洽）。

## MVP Scope

**In：**
- CAS 锐化 + 暗场提亮 + deband，单 pass、双后端
- 智能检测与自动开启（码率/分辨率 + 暗场），toast 告知，可关、记忆
- 长按看原片对比交互
- 画质面板增加"智能增强"开关（智能/开/关）
- 自动化测试用例（沿用 AutoTest 模式）

**Out：** 多 pass filter chain、NN 超分、动漫模式、分屏滑杆对比。

## Not Doing (and Why)

- **filter chain 架构** — MVP 用不上第二个 pass，不为未来需求预建。
- **NN/AI 超分** — 先验证 shader 级增强的体感，再决定是否值得上模型。
- **动漫超分（Anime4K）** — 另一条单点赛道（MIT 协议可移植、B 站已验证），留作主线验证后的二期。
- **分屏对比滑杆** — 长按看原片以 1/10 成本覆盖 80% 感知价值。
